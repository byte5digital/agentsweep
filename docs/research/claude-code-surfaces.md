# Claude Code surface inventory

Research for ticket `.scratch/ai-antivirus/issues/01-claude-code-surfaces.md`. Sources: official docs at `code.claude.com/docs/en/*` (fetched 2026-09-16) and the live files on this machine (Claude Code 2.1.273, macOS). Local file contents were read for structure only; no keys, tokens or auth values are reproduced. Claims marked **[unverified]** could not be confirmed against a primary source.

Conventions: "user" = `~/.claude` (relocatable with `CLAUDE_CONFIG_DIR`, [settings](https://code.claude.com/docs/en/settings)); "managed" = the enterprise tier (`/Library/Application Support/ClaudeCode/` on macOS, `/etc/claude-code/` on Linux/WSL, `C:\Program Files\ClaudeCode\` on Windows; [managed-settings](https://code.claude.com/docs/en/managed-settings)). On this machine the managed directory does not exist.

## 8. Project discovery

- Claude Code has no project "registry" it enumerates on startup; a project is simply the cwd (or git root) of a session. Two per-project stores exist:
  1. `~/.claude.json` -> `projects` map keyed by **absolute path** (36 entries here, including `/Users/yk-byte5` itself). Holds trust (`hasTrustDialogAccepted`), external-import approval, local-scope `mcpServers`, `allowedTools`, `.mcp.json` choices and session metrics. Trust is keyed on the git repository root (main checkout for worktrees) or the start directory outside git; home directory trust is never persisted. [permissions#project-allow-rules-and-workspace-trust](https://code.claude.com/docs/en/permissions)
  2. `~/.claude/projects/<slug>/` where `<slug>` = working-directory path with non-alphanumerics replaced by `-` (e.g. `/Users/yk-byte5/Developer/vismed` -> `-Users-yk-byte5-Developer-vismed`; names > 200 chars are truncated + hashed; `CLAUDE_CODE_PROJECT_DIR_NAME` overrides when `CLAUDE_CONFIG_DIR` is set). Holds transcripts and `memory/`. The memory `<project>` is derived from the git repo, so worktrees share it. 16 slugs locally. [sessions#where-transcripts-are-stored](https://code.claude.com/docs/en/sessions), [memory#storage-location](https://code.claude.com/docs/en/memory)
- For a scanner, the union of (a) keys of `projects` in `~/.claude.json`, (b) de-slugged `~/.claude/projects/*` names (lossy: `-` is ambiguous with `_`, `.`, `/`), and (c) a filesystem walk for `.claude/`, `.mcp.json`, `CLAUDE.md`, `CLAUDE.local.md` is the practical discovery set. ## 9. Plugin lifecycle and blocklist

**Install.** `/plugin install <name>@<mkt>` or `claude plugin install --scope user|project|local`. Marketplace is refreshed first (unless offline, seed dir, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, or blocked by policy); the plugin source is cloned/copied into `cache/<mkt>/<plugin>/<version>`; deps installed with `--ignore-scripts`; a record is added to `installed_plugins.json` and `"<name>@<mkt>": true` to the scope's settings file. `command` sources require the user to accept the exact command string (`--yes` / `--accept-command <sha256>`). Project-scope `enabledPlugins` for an external source do **not** auto-install on clone; the user must run install. `extraKnownMarketplaces` in a project file is only registered after workspace trust. [discover-plugins](https://code.claude.com/docs/en/discover-plugins), [plugin-marketplaces](https://code.claude.com/docs/en/plugin-marketplaces)

**Load.** At startup each enabled plugin's `installPath` is read; components are discovered from manifest paths or default dirs. `--plugin-dir` copies win over same-named installed plugins. Skills-dir plugins load with no registry record. Changes to `hooks/`, `.mcp.json`, `agents/` need `/reload-plugins`; `SKILL.md` edits are live.

**Update.** After session start (random delay up to 10 min) Claude Code refreshes marketplaces with `autoUpdate` and updates installed plugins on disk; the running session keeps the old path until `/reload-plugins`. `claude-plugins-official` has auto-update on by default; third-party off. `DISABLE_AUTOUPDATER` stops it (`FORCE_AUTOUPDATE_PLUGINS=1` re-enables plugins only). `command`-source plugins re-run their command once per session regardless. Old versions get `.orphaned_at` and are purged after ~14 days; `.in_use/<pid>` guards active versions. Locally observed: `playwright` at `76c85b7366c8` with `lastUpdated` 2026-09-16 and six orphaned siblings. [discover-plugins#configure-auto-updates](https://code.claude.com/docs/en/discover-plugins), [plugins-reference#plugin-caching-and-file-resolution](https://code.claude.com/docs/en/plugins-reference)

**Disable / uninstall.** Disable flips `enabledPlugins` to `false` (cache stays). Uninstall removes the record and cache dir; `${CLAUDE_PLUGIN_DATA}` survives unless it was the last scope (or `--keep-data`). Removing a marketplace uninstalls its plugins. Uninstalling a project-enabled plugin offers to write a `false` override into `settings.local.json` instead.

**Blocklist.** Two mechanisms exist:
1. *Managed policy*: `strictKnownMarketplaces` (allowlist of marketplace sources; `[]` = full lockdown), `blockedMarketplaces` (source/repo/url/`skills-dir`/`local-directory` patterns, checked before any network op), `disableCommandPluginSources`, `allowManagedHooksOnly`. Documented. [plugin-marketplaces#managed-marketplace-restrictions](https://code.claude.com/docs/en/plugin-marketplaces)
2. *Remote-fetched file* `~/.claude/plugins/blocklist.json`: the docs only name it ("Blocked plugins", [claude-directory](https://code.claude.com/docs/en/claude-directory)). The live file has `fetchedAt: 2026-03-27T08:14Z` (not refreshed since, file mtime Mar 27, mode 0600) and two entries: `code-review@claude-plugins-official` (reason `just-a-test`) and `fizz@testmkt-marketplace` (reason `security`). Per [anthropics/claude-code#80441](https://github.com/anthropics/claude-code/issues/80441) (open, label `area:plugins`) the file is fetched centrally by Anthropic and its effect is to block **model-initiated** invocation of the listed plugin's skills (error `cannot be used with Skill tool due to disable-model-invocation`), while user-typed `/name` still works; the same test entries are present on other users' machines. Fetch endpoint, refresh cadence, and whether it also blocks install/load are **[unverified]** (not in docs or the cached changelog). A scanner should treat `blocklist.json` as Anthropic-owned state: report entries, never edit.

## 11. Scanner-relevant takeaways

1. Highest-risk executable fields: `hooks[].command`/`url`, `statusLine.command`, `*Helper` keys, `env`, `mcpServers.*.command|args|env|headersHelper`, skill `` !`cmd` `` blocks and `allowed-tools`, agent `permissionMode`/inline `mcpServers`/`hooks`, plugin `hooks.json`, `.mcp.json`, `.lsp.json`, `monitors.json`, `bin/`, `workflows/*.js`, marketplace `source.source: "command"` and `headersHelper`.
2. Project-supplied hooks, `env` and helpers run under parent-folder trust and in `-p`/SDK sessions without any dialog; only `permissions.allow`, `additionalDirectories`, `.mcp.json` servers, agent frontmatter hooks/MCP, skills-dir plugins and `extraKnownMarketplaces` wait for exact-folder trust.
3. `disableAllHooks` in user settings can be overridden by a project file setting it back to `false`; only `--settings` or managed settings are authoritative.
4. Instruction-only surfaces (CLAUDE.md, rules, output styles, skill bodies, hook stdout on `SessionStart`/`UserPromptSubmit`, monitor stdout, auto-memory `MEMORY.md`) are prompt-injection vectors but cannot execute directly.
5. Allowlist (T0) anchors available on disk: `installed_plugins.json.gitCommitSha`, marketplace `plugins[].source.sha`, `.gcs-sha` for the official marketplace, `known_marketplaces.json.source`, cache dir version = commit id.
