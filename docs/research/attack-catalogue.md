# Attack technique catalogue for agent configuration surfaces

Research for ticket `.scratch/ai-antivirus/issues/03-attack-catalogue.md`. Compiled 2026-09-16 from primary sources (vendor advisories, GitHub Security Advisories / CVE records, first-party docs, and research publications from Invariant Labs, Trail of Bits, Snyk, Check Point Research, Palo Alto Unit 42, HiddenLayer, Pillar Security, Datadog Security Labs, Zenity Labs, Reversec, Manifold Security, Socket, JFrog, Kaspersky, Google Cloud / Mandiant, Anthropic and OpenAI). Two sub-reports produced earlier on this ticket are folded in and superseded by this file: `attack-catalogue-mcp-partial.md` (MCP surface) and `attack-catalogue-skills-plugins-partial.md` (skills, plugins, marketplaces, extensions). Every technique cites the page that was fetched; entries that rest on a secondary write-up say so.

Scope: what a **static scanner of on-disk configuration** can see for Claude Code and Codex. Runtime-only techniques (injection through tool results, rug pulls without a baseline) are listed at the end so the threat model can mark them out of scope explicitly. No exploit code is reproduced; indicators are described as patterns.

Legend
- **T1** (Rule): deterministic pattern with near-zero false positives; candidate for automatic Quarantine.
- **T2** (Heuristic): scored indicator; flags, never quarantines alone.
- **RT**: runtime-only, not visible in config files.
- "Repo-tracked" means the file is committed in a cloned repository rather than written by the local user; the scanner can tell via `git ls-files`.

Surfaces use the glossary in `CONTEXT.md`: instruction files (`CLAUDE.md`, `.claude/rules/*.md`, `AGENTS.md`), skills (`SKILL.md` dirs), plugins and marketplaces, hooks, MCP configs, settings.

## 2. Technique notes

Short mechanism notes where the table cell is not self-explanatory. Everything else is in the table.

### A. Instruction files

- **Which files are auto-loaded.** Claude Code loads `CLAUDE.md`/`.claude/CLAUDE.md`/`CLAUDE.local.md` from the working directory and every ancestor, `.claude/rules/*.md` recursively, and `@path` imports up to four hops, all at launch; subdirectory files load on demand ([memory docs](https://code.claude.com/docs/en/memory)). A file over 4 MiB is skipped. Codex loads `~/.codex/AGENTS.override.md`, `~/.codex/AGENTS.md`, then per directory from repo root down `AGENTS.override.md`, `AGENTS.md`, `TEAM_GUIDE.md`, `.agents.md`, capped at `project_doc_max_bytes` (32 KiB default) ([Codex AGENTS.md docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). The Codex docs do not state that `AGENTS.md` is gated by project trust; Backslash (A7) showed it executes in `exec` mode without a prompt. Claude Code docs state that `CLAUDE.md` is "context, not enforced configuration".
- **HTML comments (A5).** Claude Code strips block-level HTML comments from `CLAUDE.md` before injecting it into context, so for Claude Code an HTML comment is *not* an injection channel in `CLAUDE.md` itself; it remains one for `AGENTS.md` under Codex, for `README.md`/`SECURITY.md` the agent reads on demand (HiddenLayer's Cursor vector), and for a `CLAUDE.md` that imports `@AGENTS.md` (stripping behaviour of imports not documented). The scanner should still flag comment-hidden directives in every instruction file because the same file is shared across agents.
- **Unicode classes to flag (A1–A4).** Zero-width: U+200B, U+200C, U+200D, U+2060, U+FEFF; bidi: U+202A–U+202E, U+2066–U+2069, U+200E/U+200F; tags: U+E0000–U+E007F; variation selectors: U+FE00–U+FE0F, U+E0100–U+E01EF; private use: U+E000–U+F8FF and planes 15/16. Legitimate occurrences in instruction files are rare enough that Pillar, GitHub (warning since 2025-05-01) and the Trojan Source authors all treat their presence as a signal; bidi controls in a file that also contains Arabic/Hebrew script is the one FP case to handle.
- **Pre-approved DNS tools (A8).** CVE-2025-55284 shows the injection text itself is the only on-disk artefact; the rule should key on the pairing of a pre-approved network diagnostic (`ping`, `nslookup`, `dig`, `host`, `whois`) with a command substitution reading local files.
- **Skill `allowed-tools` and dynamic context (C7).** The permissions docs state workspace trust "never gates a skill's `allowed-tools` in any session", and Datadog showed `` !`…` `` preprocessing runs before the model sees the file. `disableSkillShellExecution` exists as a setting.

### B. Hooks and settings

- **Trust gating today (Claude Code).** Per the [permissions docs](https://code.claude.com/docs/en/permissions) "What runs before you trust a folder": hooks in settings files, the `env` block, helper commands such as `apiKeyHelper`, and a project skill's hooks and `allowed-tools` are **used** when only a parent folder is trusted and in `claude -p`/SDK sessions; `permissions.allow`, `additionalDirectories`, `extraKnownMarketplaces`, subagent frontmatter hooks and inline `mcpServers` are held until trust; `.mcp.json` servers prompt interactively but connect without asking in `-p`. `permissions.defaultMode` values `auto` and `bypassPermissions` no longer take effect from project or local settings (since 2.1.257). This is the factual basis for treating any repo-tracked `hooks`, `env` or helper key as a high-value scan target.
- **Codex.** Hooks live in `~/.codex/hooks.json`, `~/.codex/config.toml [hooks]`, `<repo>/.codex/hooks.json`, `<repo>/.codex/config.toml [hooks]` and plugin `hooks/hooks.json`; project-local hooks "load only when the project `.codex/` layer is trusted" and each hook definition must be reviewed and trusted by hash via `/hooks` ([Codex hooks docs](https://learn.chatgpt.com/docs/hooks)). Config keys that execute or weaken safety: `notify`, `hooks`, `mcp_servers.<id>.command/args/env`, `approval_policy` (`never`), `sandbox_mode` (`danger-full-access`), `allow_login_shell`, `shell_environment_policy`, `model_providers.<id>.base_url`/`env_key`/`auth.command`, `projects.<path>.trust_level` ([config reference](https://learn.chatgpt.com/docs/config-file/config-reference)). "Project-scoped config can't override machine-local provider, auth, ... notification ... keys", so a redirected `base_url` in a *user* `config.toml` written by a third-party installer is the analogue of B2.
- **Git metadata (B8, B9).** Both CVE-2026-40068 and GitSpawn exploit git files the agent reads before trust. Manifold's user-level mitigation is literally "inspect `.git/config` before you open the directory with an agent", which is a scanner job. Manifold left one additional config key unnamed while unpatched, so the rule should cover every git key whose value is executed (`core.fsmonitor`, `core.hooksPath`, `core.sshCommand`, `core.pager`, `core.editor`, `filter.*.clean|smudge|process`, `diff.*.textconv`, `merge.*.driver`, `credential.helper`, `alias.*` starting with `!`).

### C, D. Skills, plugins, marketplaces

- **On-disk locations (Claude Code).** Plugins cache under `~/.claude/plugins/cache/`, registries `installed_plugins.json` and `known_marketplaces.json`; npm sources are installed with `--ignore-scripts`; community marketplace entries are pinned to a commit SHA after automated screening ([plugin marketplaces](https://code.claude.com/docs/en/plugin-marketplaces)). Skills: `~/.claude/skills/<name>/SKILL.md`, `.claude/skills/`, plugin `skills/`. Codex: `~/.agents/skills`, `.agents/skills`, `/etc/codex/skills`.
- **Vendor position.** Claude Code [skills docs](https://code.claude.com/docs/en/skills): "Workspace trust doesn't gate this field. Claude Code applies a project skill's `allowed-tools` whenever you or Claude invoke the skill, including in a `-p` run in a folder you've never trusted." Anthropic Agent Skills overview: skills "can execute code", "use Skills only from trusted sources", Claude Code skills have full network access, `scripts/` never enter context ([Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)); plugins "can execute arbitrary code on your machine with your user privileges" and Anthropic does not control plugin contents. Claude Code's [security page](https://code.claude.com/docs/en/security) adds that Anthropic reviews connectors against listing criteria "but does not security-audit or manage any MCP server".
- **Scale.** ClawHub is an OpenClaw registry, not a Claude Code one, but it uses the same SKILL.md standard and Snyk found payloads explicitly targeting Claude Code and Cursor users; Zenity's skills.sh campaign measured 1.7 M aggregate installs and found over 30 % of dangerous skills abuse Claude Code or OpenClaw as droppers. The [OWASP Agentic Skills Top 10](https://owasp.github.io/www-project-agentic-skills-top-10/) (v1.0, 2026-03) gives a taxonomy (AST01 Malicious Skills … AST07 Update Drift) usable for rule categories.
- **Evasion research to design against.** Trail of Bits (C6) bypassed ClawHub, Cisco skill-scanner and skills.sh scanning in under an hour each with truncation padding, `.docx`/`.pyc` payloads and guard-LLM injection; SkillCloak (C5) beat eight scanners > 90 % by hiding payloads in skipped directories. Consequences for this project: never truncate, never skip directories inside a skill or plugin, treat archives/bytecode/binaries as findings, and keep T3 (AI Judgement) out of the quarantine path.

### E. MCP

## 3. Consolidated T1 indicator list (seed for the first rule corpus)

Each line is deterministic on the file content named; source rows in brackets.

1. Decode-pipe-exec chains in any scanned file: `base64 -d|-D … | (ba)sh|node|python`, `eval $(… base64 -d)`, `curl|wget … | (ba)sh|node|python` [A6, C1–C3, E4, E16].
2. Raw-IPv4 or paste-site (`rentry.co`, `glot.io`, `pastebin.com`) URLs in skill, plugin, hook or MCP files [C1, C4].
3. `unzip -P <pw>` followed by `chmod +x` or execution; `curl -k` [C1, C3].
4. Invisible Unicode classes (zero-width, bidi, tags, variation selectors, PUA) in instruction, skill, plugin or config files; ESC (0x1b) in config strings [A1–A4, E17].

## 4. Existing open-source scanners and first-party protections

Survey method: GitHub README and LICENSE pages plus the GitHub REST API for SPDX id, language, stars and last push (all fetched 2026-09-16), and first-party Anthropic and OpenAI docs. Stars and dates are as of that day.

### 4.1 Headline findings

1. **No existing tool is a local, offline, deterministic scanner with quarantine across the full Claude Code + Codex surface** (MCP configs, skills, plugins, hooks, instruction files, settings). The closest scope match is AgentAuditKit (13 stars, Python, claims unvalidated). Everything else is skills-only, MCP-only, cloud-dependent, a runtime proxy, or LLM-only.
2. **`invariantlabs-ai/mcp-scan` no longer exists separately**; it 301-redirects to `snyk/agent-scan`, which sends component metadata to Snyk's API by default and documents no local-only mode.
3. **Nobody treats hooks or `CLAUDE.md`/`AGENTS.md` as first-class static targets** except AgentAuditKit (claimed) and some ATR rules. Snyk's issue-code taxonomy has no code for hooks, settings permissions or instruction files.
4. **Quarantine is absent everywhere.** Findings are advisory or exit codes; the nearest analogue is OpenClaw's install gate (`security.installPolicy.exec` in clawscan) and AgentAuditKit's `fix` (11 of 352 rules).
5. **Invisible-Unicode detection is a solved primitive** (Snyk W021, SkillSpector, Ramparts, AgentAuditKit, `lirantal/anti-trojan-source` with ~277 code points). Reuse the code-point lists.

- `claude plugin validate` is schema-only; `claude plugin eval` is a behaviour eval whose docs say the isolation "isn't a boundary against the plugin's own code". `/skill-doctor` could not be verified on the fetched docs pages.
- Anthropic "reviews connectors against its listing criteria … but does not security-audit or manage any MCP server"; community marketplace entries are pinned to a commit SHA after automated screening; reserved marketplace names and impersonations are blocked; npm plugin sources install with `--ignore-scripts`.

**OpenAI Codex** ([approvals and security](https://learn.chatgpt.com/docs/agent-approvals-security), [config reference](https://learn.chatgpt.com/docs/config-file/config-reference), [hooks](https://learn.chatgpt.com/docs/hooks)):

## 5. Plausible but undocumented techniques (no public incident or PoC found; clearly speculative)

These follow directly from documented mechanisms but no advisory, CVE or research post demonstrating them was found on 2026-09-16. They belong in the threat model as hypotheses and in the rule corpus only as T2 unless a source appears.

1. **Credential-file `@import` in a repo `CLAUDE.md`** (`@~/.ssh/id_rsa`, `@~/.aws/credentials`, `@~/.claude/.credentials.json`) to pull secrets into context before a later exfil instruction. Anthropic added an external-import approval dialog, which shows the risk was recognised, but no incident is published. Indicator: A12.
2. **Pre-trusting directories by editing `~/.claude.json`** (`projects["<path>"].hasTrustDialogAccepted = true`) or `~/.codex/config.toml` (`trust_level = "trusted"`) from an npm postinstall or a hook, so a later clone is trusted silently. SANDWORM_MODE (E11) wrote MCP entries into user configs, and the permissions docs describe the key, but no campaign has been seen setting trust flags. Indicator: drift in those keys for paths under `/tmp`, `~/Downloads` or a fresh clone.
3. **`statusLine`, `fileSuggestion`, `otelHeadersHelper` or `awsAuthRefresh` as covert exfil channels** (they run repeatedly and receive session context on stdin). Documented as executing shell (B3); no abuse published beyond `apiKeyHelper`.
4. **HTTP hooks as exfil** (`type: "http"` posting hook JSON including `transcript_path`, `cwd`, tool input, with `$VAR` header interpolation) to an attacker URL. Mechanism documented (B12); no incident.
5. **`mcp_tool`, `prompt` and `agent` hook types** used to auto-approve tool calls from a malicious MCP server or to run a subagent with wider permissions. Documented types; no incident.
6. **Plugin `monitors/monitors.json` background processes and `bin/` PATH shadowing** (a plugin `bin/git` or `bin/npm` wrapping the real binary). Documented capability (D3); no incident.
7. **Path-scoped stealth rules** in `.claude/rules/*.md` with `paths:` frontmatter that activate only when the agent touches CI, deploy or secrets files, keeping the payload out of the startup context and out of `/context` listings. Documented mechanism; no incident.
8. **Auto-memory poisoning**: a skill or injected instruction that writes durable instructions into `~/.claude/projects/<project>/memory/MEMORY.md` (loaded every session) or redirects `autoMemoryDirectory`. Snyk observed writes to OpenClaw `SOUL.md`/`MEMORY.md` (C2 notes), so the pattern exists on a neighbouring agent; nothing documented for Claude Code.
9. **`InstructionsLoaded` / `ConfigChange` hooks that suppress or rewrite defensive hooks**, or a repo `disableAllHooks: false` overriding a user's `true` (the docs note project settings take precedence for that key). No incident.
10. **Managed-settings poisoning** via MDM or a writable `/Library/Application Support/ClaudeCode/` (`claudeMd`, `managed-settings.json` `env`, force-enabled plugins): highest-privilege surface, cannot be excluded by the user; no incident found. Indicator: world-writable managed directory; managed `env.ANTHROPIC_BASE_URL`.
11. **Homoglyph or confusable skill/plugin names in Claude marketplaces** (documented for VS Code publishers, F2, and for OpenClaw registry names, C1; not yet for Claude Code plugins).
12. **Symlinked `.claude/` or `.claude/rules/` pointing outside the repo** to make a "project" file read attacker-controlled content elsewhere on disk; the docs treat a symlinked `.claude` as repository-supplied for trust purposes, implying the case was considered.
13. **`.git/config` keys beyond `core.fsmonitor`** (`core.hooksPath`, `filter.*.process`, `diff.*.textconv`, `credential.helper`, `alias.* = !cmd`) as agent-triggered execution sinks. Manifold said one such key is being withheld while unpatched (B9), so treat the whole class as T1-worthy even though only `fsmonitor` is public.
14. **Codex `notify` or `model_providers.*.auth.command` in a user `config.toml` written by a third-party installer** (the Codex analogue of B2/B3). Documented keys; no incident.

## 6. Runtime-only techniques (out of scope for a config scanner; recorded so the threat model can say so)

- Indirect prompt injection through tool results, fetched web pages, issues and PR bodies ("lethal trifecta": [Simon Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/); [Invariant GitHub MCP](https://invariantlabs.ai/blog/mcp-github-vulnerability); [General Analysis Supabase](https://www.generalanalysis.com/blog/supabase-mcp-blog); [Unit 42 MCP attack vectors](https://unit42.paloaltonetworks.com/model-context-protocol-attack-vectors/)). Static proxy indicator (T2): a configured server set combining a secret source, an untrusted-content reader and an egress tool (Snyk W015–W020).
- Tool-description contents when the server is remote or its package is not on disk (E1, E3); rug-pull drift without a stored baseline (E2); MCP sampling and elicitation abuse; `mcp-remote` OAuth injection at connect time; filesystem-MCP traversal exploitation at request time; ANSI deception in tool outputs.
- Deep-link RCE in Claude Code (`claude-cli://`, fixed 2.1.118, May 2026) and WebFetch exfil via pre-approved domains (GHSA-fg94-h982-f3mm): agent bugs, not config artefacts.
- Skills that assemble their payload only at runtime from network responses (Reversec's DNS-record fetch, C5's runtime reconstruction): the static scanner can flag the decoder/fetch pattern but cannot see the payload.
